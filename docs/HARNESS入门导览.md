# RiskPilot Harness 入门导览

## 1. 先用一句话理解 Harness

RiskPilot Harness 是一层“受控操作台”：网页、微信小程序或 WorkBuddy 不直接碰风险公式和历史文件，而是把请求交给 Harness。Harness 带着用户身份、历史时间和权限，选择允许使用的工具，检查结果并留下可追踪信息。

它不是一个新的大模型，也不是把所有代码改成 Agent。它的价值是让同一套可靠能力可以被多个入口安全复用。

## 2. 用一次真实请求理解架构

假设微信小程序请求：“在 2025 年 4 月 30 日，用 10 万元本金和 3000 元损失预算查看某个历史案例。”

```text
微信小程序
  ↓ 只负责展示和登录
入口适配层（未来的 HTTP API）
  ↓ 创建 RuntimeContext
Harness（上下文、注册中心、策略、审计）
  ├─ get_visible_snapshot：只返回 4 月 30 日及以前的证据
  ├─ verify_evidence：检查历史文件有没有被改动
  └─ calculate_risk_budget：按 risk-v1 规则计算仓位和损失
       ↓
确定性领域规则 / 版本化历史数据
```

大模型可以在最后解释“为什么仓位是 600 股”，但不能把 600 改成 800，也不能看到 5 月份的数据。

## 3. 六个目录分别做什么

| 目录 | 可以把它理解成 | 当前内容 |
|---|---|---|
| `harness/` | 操作台规则 | 谁在调用、什么时间、追踪编号、统一返回格式 |
| `tools/` | 操作台上的按钮 | 风险预算、可见快照、证据校验 |
| `domain/` | 不可随意改变的计算规则 | 风险预算领域接口 |
| `policies/` | 门卫 | 调用前后检查产品场景和历史快照边界 |
| `infrastructure/` | 仓库管理员 | 从历史文件读取数据、检查哈希 |
| `agents/` | 讲解员 | 以后负责解释和复盘，不负责改数字 |

判断代码应该放在哪里，可以问：

- 是金融计算规则吗？放 `domain/`。
- 是一个可被多端调用的动作吗？放 `tools/`。
- 是身份、时间、权限和调用流程吗？放 `harness/` 或 `policies/`。
- 是读数据库、文件或模型服务吗？放 `infrastructure/`。
- 是自然语言解释吗？放 `agents/`。

## 4. 目前已经完成什么

### 第四步：骨架

- `RuntimeContext`：一次调用的身份证，包含用户、入口、产品场景、历史时间、快照和追踪编号。
- `ToolRegistry`：工具目录，调用方通过固定名称找到工具。
- `ToolResponse`：所有工具使用同样的成功、数据、版本、警告和错误格式。
- `PolicyGuard`：策略检查接口，后续接入具体权限和合规规则。

### 第五步：第一个确定性工具

- `calculate_risk_budget` 将 V1 风险引擎包装成结构化工具。
- 新旧结果通过固定案例逐字段比较。
- 工具结果带有 `tool_version`、`rule_version`、`snapshot_id` 和 `trace_id`。

### 第六步：证据与时间边界

- `get_visible_snapshot` 只提供 `as_of` 当日及以前的数据。
- `verify_evidence` 使用 SHA-256 检查文件完整性。
- `extract_risk_inputs` 从已校验、已截断的快照计算收盘价、ATR 和关键支撑，客户端不再自行计算。
- 数据来源和许可状态随结果返回；当前第三方样本统一标记为 `review_required`，不等于已经取得商业许可。

### 第七步：历史回放状态机

- `draw_history_case` 创建归属于当前用户的服务端实验。
- `preview_replay_position` 只做预览，不改变实验进度。
- `submit_replay_action` 每次只接受当前关的一次操作，并由服务端推进进度。
- `expected_step` 防止客户端跳关，`idempotency_key` 防止重复提交，所有权检查防止操作他人的实验。
- 当前实验进度保存在本地 SQLite，程序和电脑重启后仍可恢复；正式上线时可通过相同存储接口替换为 PostgreSQL。

### 第八步：用户、成绩与排行榜

- 内部 `user_id` 是身份依据，昵称只用于展示，因此同名玩家不会互相覆盖。
- `submit_replay_score` 只接受已经完成、且属于当前用户的服务端实验。
- 成绩提交时会重新播放数据库中的动作，客户端自报的盈亏不会被采用。
- 每个实验只能提交一次成绩；排行榜按每个内部用户的最好成绩展示。
- V2 用户和成绩写入 SQLite；V1 JSON 排行榜暂时保留，待新 API 接入后下线。

### 第九步：统一编排、策略与审计

- `build_default_orchestrator` 是所有入口共用的总入口，当前 14 个工具都必须经它调用。
- 调用前先经过场景策略：公众教育版可完成游戏，作品集演示场景只允许只读查询，不能修改实验或提交成绩。
- 风险预算计算必须绑定 `snapshot_id`，避免得到一份无法说明历史依据的数字。
- 工具内部出现意外时，编排器返回统一错误，不把程序异常直接抛给小程序。
- 每次调用都把用户、场景、工具版本、规则版本、快照、结果和耗时写入 SQLite 审计表。
- 输入和输出在审计表中只保留 SHA-256 指纹，不保存昵称等原始参数；需要复核时可用同样输入重新计算并核对指纹。

调用链现在变成：

```text
微信小程序 / 网页 / WorkBuddy
  → build_default_orchestrator
  → 调用前策略检查
  → 确定性工具
  → 调用后策略检查
  → 写入审计记录
  → 返回统一 ToolResponse
```

### 第十步：模型解释边界

- `ModelGateway` 定义统一模型接口，后续更换模型供应商不影响风险、回放和评分工具。
- `ToolResultExplainer` 只接收已经成功的 `ToolResponse`，并把完整版本和快照信息作为权威依据交给模型。
- 提示词使用 `tool-explanation-v1` 版本，明确禁止模型修改数字、补造事实、承诺收益或给出实盘指令。
- `OfflineModelGateway` 在没有模型服务时明确返回 `model_offline`，不会拿预设文案冒充真实 AI 推理。
- 当前先完成边界和离线降级；下一步再把 V1 的 OpenAI/DeepSeek 调用迁移成可替换适配器。

### 第十一步：V2 HTTP API

- 独立 `/api/v2` 服务把微信小程序的 HTTPS 请求转换成 `RuntimeContext` 和 Harness 调用。
- 健康检查可以公开访问，其他业务接口必须提供 Bearer 身份凭证。
- 没有配置身份服务时，接口默认拒绝访问，不会退化成匿名公开模式。
- `get_replay_session` 让同一用户在关闭页面后恢复挑战，其他用户不能读取或操作该实验。
- 所有响应都返回 `trace_id`，可以与 SQLite 审计记录对应。
- 当前 Bearer 适配器只用于本地联调；公开上线前必须替换成微信登录校验。

### 第十二步：V2 风险报告

- `build_risk_report` 把确定性报告领域结果和三个受证据约束的解释器结果组装成完整报告。
- `get_risk_report` 只允许内部用户读取自己的报告，不再使用 V1 按股票代码共享的进程内缓存。
- `verify_report_integrity` 分别校验结构化 JSON 和 Markdown，任意一处被修改都会显示失败。
- 报告使用 `report_id`、`user_id`、`snapshot_id`、规则版本和提示词版本追踪生成依据。
- 相同请求和幂等键只保存一次；SQLite 重启后仍能恢复完整报告。
- `list_risk_reports` 只列出当前内部用户自己的报告历史。

## 5. 四个最重要的编号

| 字段 | 回答的问题 | 示例 |
|---|---|---|
| `trace_id` | 这是哪一次调用？ | `trace-abc` |
| `snapshot_id` | 当时看的是哪份历史切片？ | `600030-2025-04-30` |
| `tool_version` | 用的是哪版工具外壳？ | `1.0.0` |
| `rule_version` | 用的是哪版业务规则？ | `risk-v1` |

以后发现某次结果有问题，可以依靠这四个编号复现，而不是只看一张无法追溯的截图。

## 6. 以后修改时的安全顺序

1. 先写清楚要改变的是入口、流程还是金融规则。
2. 金融规则变更必须产生新的 `rule_version`，不能悄悄覆盖 `risk-v1`。
3. 为变化增加测试，固定输入和预期结果。
4. 本地运行全部测试。
5. 单独提交并通过 GitHub 自动测试。
6. 最后才让网页、小程序或 WorkBuddy 使用新版本。

## 7. 你现阶段需要会解释的三句话

1. RiskPilot Harness 让多个客户端共享同一套风险、回放和评分能力。
2. 确定性工具负责数字，AI 只负责解释，不能改动工具结果。
3. `RuntimeContext` 和证据工具共同保证历史实验看不到未来数据，且每次结果可以追踪和校验。
