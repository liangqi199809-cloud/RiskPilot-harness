# RiskPilot V1 → V2 Harness 迁移计划

## 1. 迁移目标

在不破坏 V1 在线演示和现有确定性规则的前提下，将 RiskPilot 逐步迁移为多端可复用的 Harness。迁移采用“小步提交、双轨运行、结果对照、随时可退”的方式。

## 2. 当前基线

V1 当前包含：

- HTML/CSS/原生 JavaScript 网页；
- FastAPI 服务层；
- 风险计算引擎；
- 历史回放和时间隔离；
- 多 Agent 分析与离线降级；
- 纪律评分、排行榜和阵营系统；
- 固定历史快照、证据和测试数据；
- 自动化测试与 Render 在线演示。

当前主要架构问题：

- API 编排、领域计算和基础设施集中在现有后端模块中；
- 两个前端页面体积较大，界面状态和业务流程耦合；
- Agent 模块职责较多，模型接入与业务提示混合；
- 排行榜使用本地 JSON 持久化，不适合并发和长期运营；
- 缺少统一的工具契约、运行上下文、策略护栏和审计记录；
- 不同终端接入时容易重复实现业务逻辑。

## 3. 迁移约束

整个迁移期间必须遵守：

1. `main` 保留稳定 V1，不直接进行 V2 重构。
2. V2 工作仅在 `v2-harness` 及其后续功能分支进行。
3. 每次迁移只处理一个可验证能力。
4. 删除旧实现前，必须有新旧结果一致性测试。
5. 未完成授权核验的数据不进入新的公开分发渠道。
6. 密钥只能通过环境变量或密钥管理服务提供。
7. 微信小程序和 WorkBuddy 不在客户端复制风险计算逻辑。

## 4. 迁移阶段

### Phase 0：权属与基线确认

目标：确认可以继续开发，并记录 V1 的可运行状态。

任务：

- [ ] 获得原项目所有者的书面修改与发布授权。
- [ ] 确认项目名称、代码、数据和商业化边界。
- [ ] 记录 V1 当前线上地址和版本提交。
- [ ] 创建 Python 虚拟环境并锁定依赖版本。
- [ ] 完整运行现有测试并保存基线结果。
- [ ] 增加 GitHub Actions 自动测试。

验收：

- 授权记录可追溯；
- 本地和 GitHub Actions 都能运行基线测试；
- V1 行为有固定提交和测试结果作为参照。

### Phase 1：建立 V2 骨架

目标：创建新结构，但不改变 V1 行为。

任务：

- [ ] 创建 `src/riskpilot/` 包。
- [ ] 创建 `domain/`、`harness/`、`tools/`、`agents/`、`policies/` 和 `infrastructure/`。
- [ ] 定义 `RuntimeContext`、工具响应和错误模型。
- [ ] 定义 `ToolRegistry` 接口。
- [ ] 定义 `PolicyGuard` 接口。
- [ ] 增加骨架导入测试。

验收：

- V2 包可以被导入；
- V1 所有测试结果不变；
- 新目录不反向依赖网页或 FastAPI。

### Phase 2：迁移风险计算

目标：形成第一个可独立调用的确定性工具。

任务：

- [ ] 将风险计算整理为纯领域接口。
- [ ] 创建 `calculate_risk_budget` 工具。
- [ ] 增加工具输入和输出模型。
- [ ] 返回 `tool_version`、`rule_version`、`snapshot_id` 和 `trace_id`。
- [ ] 增加新旧实现一致性测试。
- [ ] 保持原 API 可继续使用。

验收：

- 固定输入下新旧结果完全一致；
- 工具无需启动 Web 服务即可测试；
- 模型不可修改工具输出。

### Phase 3：迁移证据和时间边界

目标：让所有调用共享统一的历史可见性规则。

任务：

- [ ] 定义 `EvidenceContext`。
- [ ] 创建 `get_visible_snapshot` 和 `verify_evidence` 工具。
- [ ] 集中管理 `as_of` 和 `snapshot_id`。
- [ ] 增加未来信息泄漏测试。
- [ ] 记录数据来源、许可状态和哈希。

验收：

- 任意入口都无法越过当前历史节点；
- 报告结论能够追溯到快照和证据；
- 数据篡改可被校验发现。

### Phase 4：迁移历史回放与状态机

目标：把前端隐含流程转为服务端可验证状态机。

任务：

- [ ] 定义实验状态和合法转换。
- [ ] 创建案例抽取、仓位预览和操作提交工具。
- [ ] 将挑战进度存储到服务端。
- [ ] 增加重复提交、越权、跳关和结束后修改测试。
- [ ] 保持 4 关和 17 关评分可比。

验收：

- 客户端不能伪造实验状态或成绩；
- 中断后可以恢复实验；
- 相同动作序列可在服务端复算出相同结果。

### Phase 5：迁移评分和排行榜

目标：建立可靠的长期用户和成绩存储。

任务：

- [ ] 将评分逻辑与排行榜展示拆开。
- [ ] 迁移本地 JSON 到 PostgreSQL 或兼容数据库。
- [ ] 引入内部用户 ID，昵称只作展示。
- [ ] 增加幂等提交、防刷、限流和内容过滤。
- [ ] 增加数据备份与恢复流程。

验收：

- 同名用户不会互相覆盖；
- 重复请求不会生成重复成绩；
- 服务重启后数据不丢失；
- 排行榜成绩均可由服务端重放验证。

### Phase 6：拆分 Agent 与模型网关

目标：让模型可替换，并把非确定性输出限制在解释层。

任务：

- [ ] 定义统一 `ModelGateway`。
- [ ] 拆分技术面、基本面、信息面和复盘教练。
- [ ] 对提示词和结构化输出进行版本管理。
- [ ] 保留无密钥时的明确离线模式。
- [ ] 增加输出引用、合规和数字一致性评测。

验收：

- 更换模型不影响风险、回放和评分数字；
- 模型失败时系统可安全降级；
- 每份模型报告能够追踪模型和提示词版本。

### Phase 7：接入微信小程序

目标：先发布历史风险教育 MVP。

任务：

- [ ] 实现微信登录和内部用户映射。
- [ ] 开发首页、案例选择、挑战、结果和历史记录页面。
- [ ] 将 `fetch`、DOM 和 `localStorage` 逻辑改为小程序机制。
- [ ] 重写 K 线和成绩海报。
- [ ] 配置隐私政策、服务类目、备案和 HTTPS。
- [ ] 真机测试弱网、中断恢复和授权拒绝路径。

验收：

- 小程序只调用 Harness API；
- 首版不包含实时荐股、实盘交易或收益承诺；
- 审核人员可以完成完整演示流程。

### Phase 8：接入 WorkBuddy

目标：形成面向机构培训和复盘的专业入口。

任务：

- [ ] 先制作只读复盘 Skill。
- [ ] 通过 MCP 或连接器暴露获授权工具。
- [ ] 设计机构培训 Buddy 应用工作模式。
- [ ] 增加企业身份、部门、权限和审计要求。
- [ ] 将娱乐化文案替换为机构培训表达。

验收：

- WorkBuddy 不能绕过 Harness 直接访问数据或修改成绩；
- 机构版与公众版策略隔离；
- 复盘报告保留证据、规则和模型版本。

## 5. 推荐提交粒度

每个提交只完成一个明确目的。建议顺序：

```text
Add Harness architecture and migration plan
Add V2 package skeleton
Define Harness context and tool contracts
Wrap deterministic risk engine as a tool
Add V1 and V2 risk parity tests
Add evidence visibility guard
Add replay state machine
Move leaderboard persistence to database
Add model gateway and agent boundaries
Add WeChat Mini Program adapter
Add WorkBuddy MCP adapter
```

避免在同一个提交中同时移动文件、修改计算公式和重写前端。

## 6. 分支建议

```text
main
  稳定 V1，仅接收必要修复

v2-harness
  V2 集成分支

feature/harness-skeleton
feature/risk-tool
feature/evidence-guard
feature/replay-state-machine
feature/wechat-mvp
feature/workbuddy-adapter
  短期功能分支，完成后合并到 v2-harness
```

当前初学阶段可以先直接在 `v2-harness` 上完成文档和骨架；进入实际功能开发后，再使用短期功能分支。

## 7. 回退策略

- V1 继续由 `main` 和当前在线部署提供。
- V2 未通过验收前不替换 V1 部署。
- 每个迁移能力保留新旧路径开关。
- 数据结构变更必须先备份，并提供回滚或向前修复脚本。
- 发现确定性结果不一致时立即停止迁移，不用模型解释掩盖差异。

## 8. 完成定义

RiskPilot V2 可以宣布完成首个 Harness 版本，需要同时满足：

- [ ] 至少一个网页入口和一个新入口共用工具契约；
- [ ] 风险、回放、评分均为确定性工具；
- [ ] 历史数据时间边界经过自动化测试；
- [ ] 关键调用具备版本、证据和审计记录；
- [ ] 模型可替换且失败可降级；
- [ ] 用户和成绩采用可靠数据库持久化；
- [ ] 公众版不包含实时荐股、自动交易或收益承诺；
- [ ] V1 仍可运行或有明确归档版本；
- [ ] 数据授权和项目权属已经得到书面确认。
